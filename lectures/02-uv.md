Start with lectures 1 and 2. Continue with the lecture matching your task. Examples use Python 3.12 as a learning choice, not as the newest release. Commands run in a terminal unless a Python cell is shown.

#### What uv manages

Python executes your code. uv installs or selects Python, prepares environments, manages dependencies, and runs scripts or tools.

The organization below follows a practical learning order and covers the [official uv feature areas](https://docs.astral.sh/uv/getting-started/features/).

## 1.1 Install uv

::: note Lecture 1 — Setup and Python versions
Install uv, inspect Python, and understand interpreter selection.
:::


::: info Purpose
Install the tool that manages Python interpreters, environments, and packages. You do not need to install Python first.
:::

Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Linux, macOS, or Ubuntu inside WSL:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Reopen your terminal, then verify:

```sh
uv --version
```

::: success Expected result
A uv version number. Windows and WSL are separate environments; install uv in the one where you will work.
:::

If installed with the standalone installer, update using `uv self update`. If installed through a package manager, update through that manager.

Source: [Installation](https://docs.astral.sh/uv/getting-started/installation/)

## 1.2 Install and inspect Python


::: info Purpose
Make a Python interpreter available before creating your project.
:::

```sh
uv python install 3.12
uv python list --only-installed
uv python find 3.12
```

::: success Expected result
Python 3.12 is installed, appears in the list, and has an executable path. `uv python list` without the filter also shows versions available for download.
:::

Installing Python does not create a project or install its dependencies. uv can also discover an existing compatible Python installation and download missing versions automatically.

Source: [Managing Python](https://docs.astral.sh/uv/guides/install-python/)

## 1.3 Understand Python selection versus compatibility


::: info Purpose
Avoid confusing the Python you run with the Python versions your project supports.
:::

`uv python pin 3.12` writes the interpreter preference into `.python-version`. A patch-specific pin such as `3.12.13` is more precise than `3.12`.

In `pyproject.toml`, the existing `[project]` section contains a compatibility declaration such as:

```toml
requires-python = ">=3.12"
```

This permits Python 3.12 and later; it does not restrict the project to 3.12. Use `">=3.12,<3.13"` only if your project intentionally supports that minor series alone.

After creating a project in section 2.1, you can try a different compatible interpreter:

```sh
uv python install 3.13
uv python pin 3.13
uv sync
uv run python --version
```

::: success Expected result
The environment uses the selected interpreter. The pin must agree with `requires-python`; switching Python does not guarantee every dependency supports it.
:::

Source: [Python versions](https://docs.astral.sh/uv/concepts/python-versions/)


## 2.1 Create a project and select Python

::: note Lecture 2 — Projects and dependencies
Create a project, manage its packages, run code, and reproduce its environment.
:::


::: info Purpose
Give your code a home with recorded dependencies and a selected interpreter.
:::

Run this from the parent folder where you want the project:

```sh
uv init uv-practice --python 3.12
cd uv-practice
uv python pin 3.12
uv sync
uv run python --version
```

::: success Expected result
A project folder, its configuration, a `.venv`, and a lockfile. The last command prints the project's Python version. Generated starter files can vary by uv version and initialization options.
:::

| File or folder | Meaning | Commit to Git? |
|---|---|---|
| `pyproject.toml` | Project settings, supported Python range, dependency requirements | Yes |
| `.python-version` | Interpreter selection for local uv commands | Yes |
| `uv.lock` | Resolved package versions and dependency information | Yes |
| `.venv/` | Installed project environment | No |

Do not edit `uv.lock` manually. `uv sync` creates or reconciles the environment from the project definition and lockfile.

Source: [Projects](https://docs.astral.sh/uv/guides/projects/)

## 2.2 Add, inspect, and remove dependencies


::: info Purpose
Record packages so another machine can reproduce your project.
:::

```sh
uv add rich
uv run python -c "from rich import print; print('[green]Environment ready[/green]')"
uv tree
```

::: success Expected result
`rich` is recorded, resolved, and installed. The Python command verifies its import; the tree shows dependency relationships.
:::

Development tools belong in a development group:

```sh
uv add --dev pytest ruff
uv run ruff --version
uv run pytest --version
```

Optional cleanup, after finishing section 2.3:

```sh
uv remove rich
uv remove --dev ruff
```

`uv add` and `uv remove` update the project metadata, lockfile, and environment by default. Do not run the removal commands yet if you are following the subsections in order.

Source: [Dependencies](https://docs.astral.sh/uv/concepts/projects/dependencies/)

## 2.3 Run your own Python file


::: info Purpose
Execute code using the project's interpreter and dependencies.
:::

Create `practice.py` inside `uv-practice`:

```python
import sys
from rich import print

print('[bold green]Hello from my uv project[/bold green]')
print(f'Interpreter: {sys.executable}')
```

Run it:

```sh
uv run practice.py
```

::: success Expected result
A greeting and an interpreter path inside `.venv`. Manual activation is unnecessary with `uv run`.
:::

Source: [Running scripts](https://docs.astral.sh/uv/guides/scripts/)

## 2.4 Reproduce or update an environment


::: info Purpose
Distinguish installing agreed versions from deliberately upgrading them.
:::

| Task | Command |
|---|---|
| Install from an existing, current lockfile | `uv sync --locked` |
| Check whether the lockfile matches project metadata | `uv lock --check` |
| Upgrade one package within its allowed constraints | `uv lock --upgrade-package rich` |
| Install the newly resolved versions | `uv sync` |
| Upgrade all packages within allowed constraints | `uv lock --upgrade` |
| Install without the default development group | `uv sync --locked --no-dev` |

After cloning a repository, enter its root and use `uv sync --locked`. Share source code and configuration, not `.venv`.

`--locked` rejects a stale lockfile. `--frozen` skips that freshness check. Ordinary syncing does not automatically choose every new package release. Exact syncing can remove packages that were installed manually but are absent from the selected dependency set.

Source: [Locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/)


## 3.1 Give a standalone script its own dependencies

::: note Lecture 3 — Independent scripts
Give a standalone example its own dependencies.
:::


::: info Purpose
Share a small Python example without requiring the production application or a full project.
:::

In a separate examples folder:

```sh
uv init --script standalone.py --python 3.12
uv add --script standalone.py rich
```

Keep the generated metadata comments at the top. Replace the generated program body with:

```python
from rich import print
print("[green]This example runs independently[/green]")
```

Run it:

```sh
uv run standalone.py
```

::: success Expected result
uv prepares an isolated environment from the dependencies declared inside the script. Inline script metadata makes this independent of a surrounding project's dependencies.
:::

For a one-time dependency on an ordinary script without inline metadata, use `uv run --no-project --with rich standalone.py`. This does not record the dependency in the file.

When a script no longer uses a package, remove both its import and its declaration with `uv remove --script standalone.py rich`.

Source: [Scripts](https://docs.astral.sh/uv/guides/scripts/)


## 4.1 Create only a virtual environment

::: note Lecture 4 — Virtual environments and requirements
Use existing tutorials and manually managed environments.
:::


::: info Purpose
Use uv with an existing tutorial that does not need a uv project.
:::

In a separate tutorial folder:

```sh
uv venv --python 3.12
uv pip install rich
```

Activate it if you want to use plain `python`:

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Linux/macOS/WSL:

```bash
source .venv/bin/activate
```

Then:

```sh
python -c "import rich; print('Import works')"
deactivate
```

::: success Expected result
An isolated environment, without project metadata or a project lockfile. `uv pip install` installs into an environment; it does not record a project dependency the way `uv add` does.
:::

Source: [Environments](https://docs.astral.sh/uv/pip/environments/)

## 4.2 Work with an existing requirements file


::: info Purpose
Choose whether to preserve a tutorial's workflow or adopt project management.
:::

For an existing environment-based tutorial:

```sh
uv venv --python 3.12
uv pip install -r requirements.txt
```

For an initialized uv project:

```sh
uv add -r requirements.txt
```

::: success Expected result
The first path installs requirements into the environment. The second imports them into the project's dependency declaration and updates its lockfile. Retain the original tutorial file for traceability.
:::

Source: [Projects and requirements import](https://docs.astral.sh/uv/guides/projects/)

## 4.3 Inspect a manually managed environment


::: info Purpose
Check what is installed in a tutorial's virtual environment. Run these from its folder with the intended environment selected.
:::

```sh
uv pip list
uv pip show rich
uv pip tree
uv pip check
```

::: success Expected result
A package list, details about `rich` if installed, dependency relationships, and a compatibility check of installed package requirements. This check does not test your application.
:::

`uv pip freeze` prints installed versions. `uv pip uninstall rich` removes an environment package. These commands do not maintain `pyproject.toml` or `uv.lock`; use `uv add` and `uv remove` for project-managed dependencies.

Source: [Inspecting environments](https://docs.astral.sh/uv/pip/inspection/)

## 4.4 Lock a requirements-based tutorial


::: info Purpose
Keep a requirements workflow while separating requested packages from resolved versions.
:::

Create `requirements.in` with:

```text
rich
```

In this separate tutorial folder, run:

```sh
uv venv --python 3.12
uv pip compile requirements.in -o requirements.txt
uv pip sync requirements.txt
```

::: success Expected result
`requirements.txt` contains resolved versions, and the environment matches that file. Syncing removes packages outside the supplied dependency set, so use the intended tutorial environment.
:::

`requirements.in` records your inputs; the compiled file records the resolved result. A uv project instead uses `pyproject.toml`, `uv.lock`, and `uv sync`. Keep the workflow appropriate to the resource you are teaching.

Source: [Locking environments](https://docs.astral.sh/uv/pip/compile/)


## 5.1 Run a tool without adding it to your project

::: note Lecture 5 — Command-line tools
Run utilities separately from application dependencies.
:::


::: info Purpose
Use a command-line utility in its own environment.
:::

```sh
uvx ruff --version
```

`uvx` is the shorthand for `uv tool run`. It executes a tool in an isolated tool environment.

For a persistently installed command (uninstall only when finished):

```sh
uv tool install ruff
uv tool list
uv tool uninstall ruff
```

::: success Expected result
Tools remain separate from application dependencies. For a project-controlled Ruff version, use `uv add --dev ruff` and `uv run ruff` instead.
:::

If the installed command is not found, `uv tool update-shell` configures its executable directory on your shell path; reopen the terminal afterward.

Source: [Tools](https://docs.astral.sh/uv/guides/tools/)


## 6.1 Use notebooks with the project environment

::: note Lecture 6 — Notebooks
Connect notebooks to the correct project environment.
:::


::: info Purpose
Ensure notebook imports use the same packages as the project.
:::

Inside the project:

```sh
uv add --dev ipykernel
uv run python -m ipykernel install --user --name uv-practice --display-name "Python (uv-practice)"
uv run --with jupyter jupyter lab
```

Choose **Python (uv-practice)** as the notebook kernel. In a notebook cell:

```python
import sys
print(sys.executable)
```

::: success Expected result
The interpreter path points to the project's `.venv`. A running notebook can use the wrong kernel even when your terminal environment is correct.
:::

Source: [Jupyter integration](https://docs.astral.sh/uv/guides/integration/jupyter/)


## 7.1 Recognize building and publishing

::: note Lecture 7 — Package distribution
Build a Python package and understand publishing.
:::


::: info Purpose
Understand the remaining project commands when you are ready to distribute a Python package.
:::

For a project configured for packaging:

```sh
uv build
```

::: success Expected result
Distribution archives, normally a wheel and a source archive, under `dist/`.
:::

`uv publish` uploads built distributions to a package index using the configured destination and credentials. It is a separate, intentional release action. Neither building nor publishing a Python package deploys a FastAPI web service.

Source: [Publishing packages](https://docs.astral.sh/uv/guides/package/)


## 8.1 Locate storage and perform optional maintenance

::: note Lecture 8 — Maintenance and troubleshooting
Inspect storage, maintain uv, and diagnose common problems.
:::


::: info Purpose
Understand where uv keeps reusable downloads, tools, and managed interpreters.
:::

```sh
uv cache dir
uv tool dir
uv python dir
```

::: success Expected result
Directory paths. These commands inspect locations without changing them.
:::

Optional actions, used only when needed:

| Command | Effect |
|---|---|
| `uv cache clean` | Clears cached entries; later operations may download or rebuild them |
| `uv cache prune` | Prunes outdated cache entries; current documentation also includes centralized project environments |
| `uv python uninstall 3.13` | Removes a uv-managed interpreter you no longer need |
| `uv self update` | Updates a standalone uv installation |

Cache maintenance does not replace dependency management. Keep interpreters still needed by your environments. Update package-manager installations of uv through their package manager.

Source: [Feature overview — utilities and Python versions](https://docs.astral.sh/uv/getting-started/features/)

## 8.2 Recognize common problems


| What you see | Plain-English meaning | Technical interpretation |
|---|---|---|
| `uv` is not recognized | The terminal cannot find uv | Installation or `PATH` discovery issue |
| `ModuleNotFoundError` | This Python cannot see the package | Missing dependency or wrong interpreter/kernel |
| No solution found | Requested versions cannot coexist | Conflicting package constraints or Python compatibility |
| Python version is incompatible | The selected Python is outside the project's range | Pin conflicts with `requires-python` |
| Locked operation fails | Configuration and lockfile disagree | Lockfile requires an intentional update |

Useful inspection commands:

```sh
uv --version
uv run python --version
uv run python -c "import sys; print(sys.executable)"
uv tree
uv help
uv help add
```

Inspect the reported interpreter and dependency requirements before changing versions.
