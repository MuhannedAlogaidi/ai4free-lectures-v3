#  HOW TO USE THIS FILE
#   1. Copy it:  cp .env.example .env
#   2. Fill in ONLY the services your project uses. Delete everything else.
#   3. NEVER commit .env. Add ".env" and ".env.*" to .gitignore
#      (keep only ".env.example" in git, with values empty).
#   4. Use different keys for dev / staging / production.
#   5. In production, prefer a secrets manager (AWS Secrets Manager, GCP Secret
#      Manager, Azure Key Vault, Doppler, Infisical, 1Password, Vault).
#
#  LEGEND (used above every service)
#   Source     = official console / dashboard and docs
#   Use when   = the typical reason to pick this service
#   How to get = the steps to create the key
#   Format     = typical key prefix (helps catch keys pasted in the wrong place)
#   Free tier  = whether you can start without paying (may change — check site)
#
#  Then, directly above EACH variable:
#   # Get your API key from <url>   (or "Get it from" / "Set it yourself")
#   # Usage: what this specific value is for
#
#  SECURITY RULES
#   - Vars prefixed NEXT_PUBLIC_ / VITE_ / EXPO_PUBLIC_ are sent to the browser.
#     NEVER put a secret key behind those prefixes.
#   - Restrict keys where the provider allows it (IP, domain, scopes, budget caps).
#   - Rotate any key that was ever pasted into chat, a ticket, or a screenshot.
#   - Dashboard menu names change over time; if a path below is out of date,
#     look for "API Keys", "Tokens", "Credentials" or "Developer" in settings.
# =============================================================================
